# V0.49_SPEC — Swimmer persistence across set-fragment timing launches

Status: APPROVED (2026-08-22 — user "go")
Branch: v2.0 (post-8b2cdac)

## Problem

Every per-fragment timing launch creates a fresh session and forces the coach through the swimmer-selection modal — even mid-workout, when the same swimmers are standing on the same deck. User directive (2026-08-22, verbatim): "assume the same swimmers will attend the whole workout… Skip the selected Swimmers modal and go straight to the stopwatch."

## Core assumption (user-stated, deliberate)

Swimmers do not leave or join mid-session. Attendance is set once per workout and persists for every subsequent fragment launch. The edge case (a swimmer does leave/join) is handled explicitly via an "Edit Attendees" button — NOT by re-showing the modal every time.

## UX flow (locked)

```
Fragment CTA tap
   │
   ├─ roster found for this workout's latest session
   │     └─ TimingView straight away — roster strip: "Jack · Ariana" + Edit
   │          Edit → SessionStartView sheet, roster pre-selected
   │
   └─ no roster (first fragment of the day / legacy)
         └─ SessionStartView picker (today's flow, unchanged)
```

1. Coach taps fragment CTA on the WorkoutDetail page.
2. App queries the most-recent session for this workout with a non-empty `session_roster` (2s budget; on any error, fail open to the picker).
3. Hit → skip picker, launch TimingView with roster pre-selected; names shown as a roster strip above the stopwatch so the coach can visually verify who's in.
4. Miss → today's SessionStartView picker, unchanged.

## Data source (single source of truth)

Most recent `sessions` row (by `started_at`) for the `workout_id` having rows in `session_roster`. Lane/position from the roster feed wave allocation unchanged. If the most recent session has no roster rows (legacy data), fall back to the picker.

## Session identity

`launchFragmentTiming` currently mints a fresh UUID per tap (WorkoutDetailView.swift:579). This spec changes that: one session id per workout per day — the first fragment launch creates it, subsequent launches REUSE it, so wave_assignments/recorded_times/session_roster stay grouped under one session. Sessions-row insert moves to upsert semantics (already upsert at SessionStartViewModel:302).

## Edit Attendees button

- Location: below Edit Workout in `actionButtons(workout:)` (user-stated), same secondary-button style.
- `editWorkout()` is currently a stub (WorkoutDetailView.swift:152) — leave the stub alone; add a separate Attendees action.
- Opens SessionStartView in edit mode: current roster pre-selected, coach adds/removes, Done re-persists to `session_roster` for the ACTIVE session id.
- Available any time, including before the first fragment (manual cold-start fallback).

## Non-goals

- No mid-session arrival/departure modeling, no attendance-history UI.
- No changes to wave allocation math — roster feeds WaveAllocator unchanged.
- No changes to TimingService save paths (stable since 985dddf).
- No cross-workout/cross-day attendance carry-over.

## Slices (serialized — both touch WorkoutDetailView.swift)

### Slice 1 — Roster lookup + skip-the-picker launch + Edit Attendees entry point
- `WorkoutService.fetchLatestRoster(workoutId:) -> (sessionId: String, roster: [Swimmer])?` — most-recent-session roster joined to swimmers. ≤2 round trips, fail-open nil → picker.
- `launchFragmentTiming`: on roster hit, skip `showSessionStart`; set `activeSession` + `timingPrefill` directly with the EXISTING session id. On miss, today's flow.
- `actionButtons` gains "Edit Attendees" below "Edit Workout" (secondary style) → SessionStartView edit mode, Done upserts `session_roster` for the active session id.
- Gate: macstudio xcodebuild + simulator check — roster-hit path lands on stopwatch with strip visible; no-roster path unchanged.

### Slice 2 — Roster strip in TimingView + live-edit round-trip
- Roster strip above stopwatch: names joined "Jack · Ariana", inline Edit tap → SessionStartView sheet (pre-selected), Done re-persists session_roster + wave_assignments.
- Strip hides when roster empty. Style: fog-on-inset monoChip 11 JBM, Haptics.selection on expand.
- Gate: macstudio xcodebuild + simulator round-trip — add swimmer mid-timing → wave_assignments gains row.

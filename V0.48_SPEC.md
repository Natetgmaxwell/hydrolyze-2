# V0.48_SPEC — Fragment times: progressive disclosure + multi-swimmer attribution

Status: IMPLEMENTED — slices 1–3 committed (V0.48 S1–S3); roster persistence fix live in ae2ee0a. E2E verified on simulator 2026-08-29.
Branch: v2.0 (post-985dddf)

## Problem

V0.47 renders every saved fragment time as an inline chip. With multiple
swimmers × multiple passes (2×-through sets), the fragment row overflows a
390pt screen and buries the CTA. Times are also anonymous — the map is
`[fragmentId: [Int]]` with no owner, so 4 times from 2 swimmers render as
4 indistinguishable chips.

## Locked decisions

1. **Data model** — `recordedTimesByFragmentId: [String: [FragmentTimeRecord]]`
   where `FragmentTimeRecord = { swimmerName: String?, timeMs: Int, capturedAt: Date }`.
   One array element per swimmer per pass.
2. **Owner attribution** — load path joins swimmer names via
   `paired_swimmer_id`. Solo / unattributed rows → `swimmerName: nil`.
3. **Display tiers, per fragment** (count-driven, recompute automatic):
   - 0 times → no UI (unchanged)
   - 1–2 times → inline chips; name-prefixed when owner known (`Jack 1:41.7`)
   - 3+ times → ONE aggregate chip: `4 saved ▸` → tap opens sheet
4. **Sheet** — `.presentationDetents([.medium])`; title = fragment label;
   one row per swimmer (body 15 name, numeric 15 JBM passes, `·` separators);
   unattributed times grouped in one trailing row. Swipe-to-dismiss. No push.
5. **Live capture** — `onRecord` appends to the map; tier recomputes. The
   1→2→collapse transition at 3 is the accumulation feedback.
6. **Chip tap ≠ CTA tap** — aggregate chip never launches timing; distinct
   hit target ≥44pt.
7. **History scope** — session-pure: this workout's times only. Cross-week
   history / PB comparison out of scope (revisit after real usage).
8. **Style** — chip: monoChip 11 JBM, fog on inset. Sheet bg: raised.
   Coral stays exclusive to the Time CTA (≤20% rule). Motion: gentle (0.35)
   on chip appear; sheet system default. Haptics: selection on chip tap.

## Non-goals

- Editing/deleting times from the sheet (discard lives in the review screen)
- Cross-workout history, PB deltas, sorting controls (chronological only)
- Landscape / iPad layout work

## Slices

1. **Data** — `FragmentTimeRecord` model, swimmer-name join in
   `loadFragmentTimes`, `onRecord` payload unchanged shape. Gate: build.
2. **Tiers + sheet** — `FragmentCTARow` tier logic, aggregate chip,
   `.medium` sheet with swimmer rows. Gate: build + simulator visual.
3. **Sweep** — accessibility labels, contrast check on chip/inset pair,

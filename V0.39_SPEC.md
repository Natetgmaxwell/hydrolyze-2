# V0.39 — Drop Rule: individualized rest extension for anaerobic sets

**Status:** LOCKED. Owner: build profile. Branch: v2.0.
**Source:** `docs/research/2026-08-15-3mt-drop-rule-zones.md` §3.3 + §4 (approved 2026-08-15). This spec implements Feature 2 of that doc. Recovery flywheel and zones are V0.40+.
**Grounding verified 2026-08-18:** no `set_rest_events` table, no `RestCountdown`/rest-timer code anywhere in `ios-native/Hydrolyze/Sources/`; the 10ms `Timer.publish` cadence lives at `TimingViewModel.swift:530`; `workout_set_completions` exists (set completion tracking). Latest migration: `20260815120000_3mt_mode.sql`.

## Why

Eva Piatrikova's drop rule is default-to-assign applied to rest: when a swimmer's rep time drops >0.5s (50m) / >0.25s (25m) off their standard, the engine extends their rest by +30s; a second strike extends +60s. Most coaches under-rest anaerobic sets — the drop rule removes the mental tally and makes the extension visible and revertible in one tap. Nathan uses it with his squad this week.

**Hydrolyze-unique twist (approved):** the standard is the **predicted time** from `HistoricalTimePredictor` (maturity ≥ .reliable, 6+ samples); fallback to rep 1 (Eva's rule) when prediction is immature or absent. The prediction already inherits gear/suit/start calibration.

**Zone gate (v1, approved):** the rule fires only on anaerobic sets — `intensity_label ∈ {hard, race}` (or `intensity_type` mapping to sprint/hard). Aerobic sets don't get individualized rest. The zone-aware refinement lands with V0.40.

## Contract

### Slice 1 — DB migration (additive only)

One migration, `supabase/migrations/YYYYMMDDHHMMSS_drop_rule_rest_events.sql`:

```sql
CREATE TABLE IF NOT EXISTS set_rest_events (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id        uuid NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  workout_set_id    uuid NOT NULL REFERENCES workout_sets(id) ON DELETE CASCADE,
  swimmer_id        uuid NOT NULL REFERENCES swimmers(id) ON DELETE CASCADE,
  rep_index         integer NOT NULL,
  rep_time_ms       integer NOT NULL,
  standard_ms       integer NOT NULL,
  base_rest_sec     integer NOT NULL,
  extended_rest_sec integer NOT NULL,
  delta_sec         integer NOT NULL,
  strike_count      integer NOT NULL DEFAULT 1,
  standard_source   text NOT NULL CHECK (standard_source IN ('predicted', 'rep1')),
  reverted          boolean NOT NULL DEFAULT false,
  created_at        timestamptz DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_rest_events_swimmer ON set_rest_events(swimmer_id, workout_set_id);
```

RLS: same pattern as `swimmer_pbs` — coach sees events for their swimmers (via `swimmers.coach_id IN (SELECT id FROM coaches WHERE auth_id = auth.uid())`). No backfill.

### Slice 2 — `RestCountdownModel` + drop-rule state machine (pure logic)

New file: `ios-native/Hydrolyze/Sources/Models/RestCountdownModel.swift` (or `Services/` per the project's file placement for pure logic — match V0.38's `ThreeMinuteTestAnalyzer` pattern: pure struct, unit-testable, no DB, no async).

State per swimmer: `strikes`, `currentExtensionSec`, `standardMs`, `standardSource`. Common clock: `baseRestSec`, `remainingSec`, `extendedRestSec` (shared countdown).

Rules (from research doc §4.1, approved):
1. On each rep completion (LAP → rep time finalized), evaluate per swimmer:
   - Standard = `HistoricalTimePredictor` prediction at this set's (distance, intensity, gear) **if maturity ≥ .reliable (6+ samples)**; else rep 1 time.
   - Strike if `repTime > standard + threshold` (0.5s for 50m, 0.25s for 25m — linear scaling by distance).
   - Strike 1 → extension +30s. Strike 2 → +60s. Strikes reset when the swimmer hits the standard again.
   - Gate: fire only when set intensity is hard/race. Otherwise no evaluation.
2. Common clock + per-swimmer flags (approved v1): countdown shows the common clock; each swimmer's flag shows their personal extension.
3. Revert: one tap → rest back to base, event written with `reverted = true`. Coach is authority.

Acceptance:
- Unit tests: strike on 50m rep > standard + 0.5s; no strike within threshold; second strike escalates +60s; strike reset on good rep; immature prediction (maturity < reliable) falls back to rep 1; aerobic set → no evaluation; revert restores base rest.
- Pure function — no DB calls in the model.

### Slice 3 — TimingView: countdown + inline badge + revert

In the timing screen, when the active set is anaerobic with an interval (`interval_text` parses to seconds):

1. **Countdown display** alongside the stopwatch (the app's first rest timer — reuse the existing 10ms `Timer.publish` at `TimingViewModel.swift:530`; no new timer machinery). Between sets, when the coach is on rest, the countdown counts down from the common clock.
2. **Inline badge** (non-intrusive confirmation surface — NEVER modal): when a swimmer strikes, show e.g. `Rep 3: 27.8, +0.6 → rest 5:00` with a one-tap revert. One-tap revert restores base rest and writes `reverted = true`.
3. Per-swimmer flags visible in the badge line (e.g. `Ariana +30s, Jack holding`).

Anti-patterns (explicitly avoided):
- No modal sheets for rest extension (non-intrusive surface principle)
- No new vocabulary — "rest", "strike", "extended" in coach words
- The engine never silently extends — every extension is visible in the badge and revertible

Acceptance:
- Simulator: anaerobic set with interval shows countdown on rest; a slow rep triggers the badge with the correct extension; one-tap revert restores base rest
- Aerobic set: no countdown chrome changes (badge absent)

### Slice 4 — Save path: `set_rest_events` persistence

On set completion (or on each event — match the existing `workout_set_completions` save pattern in `TimingViewModel.save()`), write `set_rest_events` rows: one per extension decision, including reverted ones (the engine learns the coach disagreed — `reverted = true` recorded, rest not extended).

Acceptance:
- After a timed anaerobic set with a strike, `set_rest_events` contains the event rows (verify via live-DB query)
- A reverted extension is written with `reverted = true`
- No rows written for aerobic sets

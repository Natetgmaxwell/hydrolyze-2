## Requirements

Recognition targets (case-insensitive, word-boundary-safe):
- "3MT", "3-MT", "3 MT"
- "3-min all-out", "3 min all out", "3-minute all-out", "3min all out" (allow min/minute/mins/minutes, hyphen/space variants, "all-out"/"all out")
- "3 min test", "3-minute test", "3min test"
- Also tolerate a leading stroke word: "3MT free", "free 3MT", "3 min all-out kick" (stroke parse already handles free/kick — the 3MT marker must not break it).

When a set line matches a 3MT marker:
1. `intensity_type = '3mt'` (new type) with label "3-minute all-out" (or "3MT" if the coach wrote the short form — pick ONE canonical label: "3-minute all-out"; simple is fine).
2. `reps = 1`
3. `distance = 25` (split distance, per spec)
4. No interval (continuous swim) — do not parse an interval from the 3MT line even if present.
5. The stroke still parses normally (default Free).

Workout-level `session_type = '3mt'`: the workout's PRIMARY set is a 3MT → the app sets the workout row's session_type when saving. For the parser layer:
- Swift `WorkoutParser`: add a computed helper on the parsed result, e.g. `ParsedWorkout.is3MT` (true when any repGroup has intensity type 3mt — check how ParsedWorkout is shaped; put the helper where it fits naturally, or a static func `WorkoutParser.is3MT(_:)`).
- Edge function: export a `workoutIs3MT(workout: Workout): boolean` helper + set it in the response payload as a top-level `session_type: "3mt" | "training"` field on the Workout object ONLY IF adding the field doesn't ripple through the LLM schema validation (validateLLMOutput) — if it does ripple, keep the helper and let the iOS side compute it; document the choice in your report.

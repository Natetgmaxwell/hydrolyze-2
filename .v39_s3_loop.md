## Requirements (spec §Slice 3)

When the active set is **anaerobic with an interval** AND we're in the single-swimmer flow (a swimmer is selected — the rep attribution is unambiguous):

1. **Countdown display**: between reps, show a rest countdown alongside the stopwatch. Reuse the EXISTING 10ms `Timer.publish` cadence (line 530, `tick()` at 1313) — NO new timer machinery. In `tick()`, if a `RestCountdownModel` is active and state == .running, call `model.tick()` once per SECOND (accumulate the elapsed-ms between calls; only decrement when a full second has passed — do NOT decrement 100×/second from the 10ms tick). The countdown shows `model.remainingSec` as "m:ss". Render it in `runningView` near the stopwatch, styled like the existing 3MT countdown (smaller monospaced, secondary). Use existing type scale — `Color.accentAmber` when < 30s, else white 0.85. NO new colors/fonts.
   - When is the countdown "active"? Start it when the coach is on rest. Simplest correct v1: start the countdown at `start()` (from `baseRestSec`), count down to 0, then STOP counting (show "0:00" or hide) until the coach taps LAP to start the next rep. On LAP, reset the countdown to `baseRestSec` (or the extended rest if a strike just landed). This matches pool-deck reality: coach starts the stopwatch, swimmers do the rep, coach taps LAP at the wall, then rest counts down.
   - Spec §Slice 3 line 70: "Between sets, when the coach is on rest, the countdown counts down from the common clock." The common clock is `model.remainingSec`.

2. **Build the `RestCountdownModel` in the VM**: at `start()` (or in the running state), construct `RestCountdownModel(baseRestSec: intervalToSeconds(interval) ?? 0, setIsAnaerobic: isAnaerobic)` where `isAnaerobic` = intensityLabel ∈ {hard, race} (map from `IntensityLevel` displayName "Hard"/"Race pace" or the raw intensity). Store as a `@Published var restModel: RestCountdownModel?`. Reset it on `reset()`/new session.

3. **Drop-rule evaluation on LAP** (spec §Slice 3 badge): in `lap()`, when a `restModel` is active and the swimmer is selected (single-swimmer flow):
   - The rep's time = `newLap.splitMs` (the split for THIS rep, not the cumulative elapsed).
   - **Standard source**: rep 1 time = the FIRST lap's splitMs for this swimmer in this set. Predicted standard = `HistoricalTimePredictor`/`PBService.fetchPrediction` prediction for this (swimmer, distance, intensity) IF maturity ≥ .reliable. **Important**: the save flow already fetches predictions inside `save()`. For the LIVE badge you need a prediction BEFORE save. Use `PBService().fetchPrediction(swimmer:set:intensity:gear:prefs:recordedTimes:pbs:calibration:)` — but the VM doesn't hold `Swimmer`/`recordedTimes`/`pbs` live. **v1 simplification (in-spec)**: use the **rep-1 standard** for the LIVE badge (Eva's rule is literally rep-1, and the predicted-standard refinement lands via the save path in Slice 4). So `predictedStandardMs = nil`, `predictionMaturity = nil`, `rep1TimeMs = first lap's splitMs`. The maturity-gate still works (falls to rep1). Document this clearly — the predicted standard is the Slice 4 save-time concern, not the live badge.
   - Call `restModel.evaluate(swimmerId:repIndex:repTimeMs:distanceMeters:predictedStandardMs:nil:predictionMaturity:nil:rep1TimeMs:)` with `distanceMeters = self.distance`.
   - If the evaluation returns a non-nil result with `struck == true`, surface the inline badge (below).

4. **Inline badge** (spec §Slice 3 line 73-76, non-intrusive, NEVER modal): a small inline line in `runningView` (directly under the countdown / above the LAP list). Format: `Rep N: 27.8, +0.6 → rest 5:00` with a one-tap revert button. Use the evaluation's fields:
   - `Rep N` = `evaluation.repIndex`
   - `27.8` = the rep time in seconds (`repTimeMs / 1000`, 1dp)
   - `+0.6` = `(repTimeMs - standardMs) / 1000`, 1dp (the over-standard delta)
   - `rest 5:00` = `evaluation.extendedRestSec` formatted "m:ss"
   - One-tap revert: a small button (e.g. "UNDO" or "REVERT") that calls `viewModel.revertRestExtension()` which calls `restModel.revert(swimmerId:)` and stores the `RevertResult` (so Slice 4 can persist it). After revert, the badge shows base rest.
   - Keep it compact, one line, `caption`/`body` type scale, amber accent. NO modal. NO new vocabulary — "rest", "strike", "extended" in coach words. Do NOT say "standard" — use "their usual" or just show the delta.

5. **Aerobic set: no countdown chrome** (spec acceptance). `isAnaerobic == false` → `restModel` stays nil → no countdown, no badge. Behavior identical to today.

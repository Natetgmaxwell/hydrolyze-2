### The zone model (research doc §5.1, exact constants — approved decisions table #1)

Boundaries as constants of critical speed (CS):
- **Easy/Steady** boundary = 0.89 × CS
- **Steady/Hard** boundary = CS
- **Hard/Sprint** boundary = 1.035 × CS
- **Peak speed** = top of Sprint (the swimmer's observed peak)

```swift
struct TrainingZones: Equatable, Sendable {
    let easy: PacePer100m      // 0.89 × CS
    let steady: PacePer100m    // CS
    let hard: PacePer100m      // 1.035 × CS
    let sprint: PacePer100m    // peak
    let criticalSpeedMps: Double
    let sourceTrialNumber: Int
}
```

`PacePer100m` — a small value type holding the boundary m/s and its rendered per-100m pace string. It should expose the pace in "m:ss/100m" format. REUSE `thresholdPaceString(criticalSpeedMps:)` from ThreeMTReviewSupport for the string (guard against non-finite / <= 0 → pace string nil or "—").

Zone NAMES in coach vocabulary (mandatory — NEVER "zone 1–4", NEVER "LT"/"CS"/"vVO2max"):
- Easy / Steady / Hard / Sprint

### API

- `static func derive(criticalSpeedMps: Double, peakSpeedMps: Double, sourceTrialNumber: Int) -> TrainingZones?`
  - Returns nil iff CS <= 0 or non-finite (defensive — never crash). Peak is clamped to be >= the sprint boundary when the observed peak is below 1.035×CS (so sprint pace never inverts below hard); when peak is nil/invalid, sprint = the 1.035×CS boundary itself.
  - Boundaries: easy = 0.89×CS, steady = CS, hard = 1.035×CS, sprint = max(peak, 1.035×CS).

### Acceptance (spec §Slice 1)

- 1.33 m/s CS → boundaries 1.184 (easy), 1.33 (steady), 1.377 (hard) m/s; peak >= 1.035×CS means the swimmer reaches Sprint.
- Per-100m paces render as mm:ss (e.g. 1.33 → "1:15/100m" since 100/1.33 = 75.19s → 75s = 1:15).
- Never crashes on edge input (0, negative, nan, infinity CS).

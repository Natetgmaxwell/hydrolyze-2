## The three surfaces

### 1. WorkoutDetailView v2 (this spec's core)

One screen, top to bottom:

1. **Header** — title, date, status pill (existing tokens). No buttons. Navigation is the system back-swipe; the broken top-left button is deleted.
2. **Attendee row** — inline badge `8/12 attending`, tap → popover (non-modal, per non-intrusive-surface rule). Only if the workout is scheduled/in-progress.
3. **Structured preview** — the parser's output, not the coach's prose. Glancable loop syntax:
   - Set row: `4× 50 FREE · 1:30` (mono, numericLarge)
   - Fragment lines indented under the parent: `75 fast`, `25 easy` (monoChip)
   - DESCEND ladder rendered as its ladder (`28.0 → 27.5 → 27.0 → 26.5`), not prose
   - Zone/intensity as color-coded token (existing accentAmber/accentCyan discipline; no new vocabulary)
   - Render source = the same projection the builder preview uses (now fixed to carry fragment structure). The details page and the builder preview must NEVER diverge again — one shared row-render component (extract from `WorkoutDetailView.buildParsedWorkout` / builder preview into a single `WorkoutStructureView`).
4. **Edit affordance** — small `Edit` in the toolbar → sheet with the ORIGINAL PLAIN TEXT submitted to the parser, re-parse on save. No structured editing UI, ever. The parser is the product; the edit surface is its front door.
5. **Floating next-effort CTA** — pinned bottom, above the safe area:

   ```
   TIME NEXT · 50 FREE @ 100 PACE
   Rep 1 of 8                        ▶
   ```

   - Names the next TIMEABLE fragment (has distance + non-easy intensity). Non-timeable fragments (warmup, kick-easy) are skipped silently — the CTA never points at them, but they remain visible in the structured preview.
   - `N of M` counts only timeable reps within the current set (matches Nathan's "1 of 8" for 8×50).
   - After a timed rep completes, the CTA advances (`2 of 8`), completed rep gets a tick in the preview, and the CTA label updates to the next fragment when the set rolls over.
   - Workout fully timed → CTA becomes `SESSION COMPLETE ✓ · Review` (routes to SessionReviewView).
   - No timeable fragment exists → CTA hidden (Hormozi: no dead affordances).

### 2. Stopwatch — full-screen element

Presented via `.fullScreenCover` from the CTA. A real stopwatch, nothing else:

- Eyebrow (single line, top): `50 FREE @ 100 PACE · REP 1 OF 8` — what the swimmers are swimming.
- Center: huge mono running time (`displayHuge`, JetBrains Mono), current lap count.
- One prominent LAP button (volume-down equivalence maintained). START optional per the locked V0.54 auto-start-on-first-LAP refinement — first LAP tap can be the start.
- Bottom: last 2–3 laps in small type (`LAP 3 0:24.5`) — count-verification without scrolling. Full lap list only in review.
- No menus, no cards, no chrome, no color except the 20% accent flash on lap capture (80/20 rule, Nathan's 2026-06-14 lock).
- Close (swipe or X) → back to WorkoutDetailView; CTA advanced; rep ticked; recorded_times row already persisted (existing onRecord persistence path).

### 3. Edit sheet

- Plain text only (the original submitted text), mono font, `Re-parse & Save` button.
- On save: re-run parser → update workout + sets → structured preview re-renders. Parse errors shown inline in the sheet (Hormozi: show progress/certainty, never a silent failure).

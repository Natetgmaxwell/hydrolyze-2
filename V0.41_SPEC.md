# V0.41 — Zone-term set writing: "8×100 Steady on 1:30"

**Status:** LOCKED. Owner: build profile. Branch: v2.0.
**Source:** `docs/research/2026-08-15-3mt-drop-rule-zones.md` §5.2 (approved 2026-08-15). Feature 4 remainder — the set-writer side of zones, deferred from V0.40 with its own spec because it changes the parser contract.
**Grounding verified 2026-08-18:** parser path is LLM-first (`supabase/functions/parse-workout/` MiniMax-M3 + `WorkoutParser.swift` regex fallback). `RPEParser.swift` handles RPE words (T2/T4). Intensity labels already include zone-ish words (easy/steady/hard/sprint map to intensity types). The timing engine resolves per-swimmer pace targets at timing time — that is where zone words become paces.

## Why

Once zones exist (V0.40), a coach writes "8×100 Steady on 1:30" and every swimmer with a usable profile gets their own target pace for that set — individualized prescription from one line of workout text. This is the "democratization" story completed: the club coach writes zone terms like a sport scientist, without any of the hardware.

## The contract change (named)

Today, intensity words parse to a static intensity type/label. **Zone words become a new parse output:** `zone_term: "steady" | "easy" | "hard" | "sprint" | null` on the repGroup (or fragment). The parse does NOT resolve a pace — pace resolution is per-swimmer at timing time (the swimmer's zones from their profile), so one workout text serves a mixed squad correctly.

- Regex path (`WorkoutParser.swift`): recognize the four zone words in set text → `zone_term`.
- LLM path (`parse-workout` system prompt + schema): same four words → `zone_term` field. The existing intensity mapping stays (zone words also map to their intensity type for non-zone features — "hard" → hard intensity).
- iOS `ParsedRepGroup`/`ParsedFragment`: optional `zoneTerm` (decode-compatible, `decodeIfPresent`).

## Contract

### Slice 1 — Parser: zone_term extraction (4-place sync)

1. Node prototype → 2. Deno/edge (`_llm.ts` + `index.ts`) → 3. parse-workout prompt → 4. iOS decode. Same 4-place sync discipline as the fragment pipeline (hydrolyze-parser-engineering skill).

Acceptance:
- "8×100 Steady on 1:30" parses with `zone_term: "steady"`; "4×50 Sprint" → `"sprint"`; plain "8×100 free on 1:30" → `zone_term: null` and behaves exactly as today.
- Ladder verifier (`scripts/verify-parse-ladder.sh`) stays green after deploy.

### Slice 2 — Timing: per-swimmer zone pace resolution

In the timing flow, when the active set has a `zone_term`:

- Each swimmer's pace target = their zone pace from `TrainingZoneService` (V0.40) at the zone term, if they have a usable profile.
- Swimmers without a usable profile: fall back to the standard prediction path (HistoricalTimePredictor) — the set still times normally; no dead rows.
- The resolved target feeds the same drop-rule standard machinery (V0.39/V0.40): a swimmer missing their zone target on a zone set gets the rep-1 fallback, never a phantom strike.

Acceptance:
- Simulator: zone set with a mixed squad — profiled swimmers show their zone pace as target; unprofiled swimmers time normally with predicted targets; drop rule evaluates profiled swimmers against the zone pace.

### Slice 3 — Builder: zone terms as first-class input

The workout builder's natural-language input already accepts free text. No new UI chrome: zone words work in the text. A coach writing "Steady" gets immediate feedback via the parsed preview showing the zone term chip. If the builder has a structured intensity picker, add the four zone words to it.

Acceptance:
- Builder preview shows the zone term on the parsed row; saving persists it; re-opening shows it.

## Boundaries

- **Always:** zone words parse to `zone_term` + their intensity type; pace resolution at timing time, never at parse time; no-profile swimmers fall back cleanly
- **Ask first:** adding new zone words beyond the four; structured intensity picker changes beyond adding the four words
- **Never:** breaking the 4-place sync (a field in one place but not the others silently kills the CTA path); touching `PairingEngine.swift`

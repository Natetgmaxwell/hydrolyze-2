# V0.45 — 3MT as a first-class workout template (Dr Eva's protocol)

**Status:** LOCKED. Owner: build profile. Branch: v2.0.
**Sources:** `docs/research/2026-08-15-3mt-drop-rule-zones.md` §1 (protocol, equipment, familiarisation); V0.38 spec (3MT session type, shipped); gbrain `concepts/3mt-drop-rule-zones-hydrolyze`.
**Grounding verified 2026-08-18:** 3MT works as a session type (V0.38: `workouts.session_type` column exists, `intensity_type = "3mt"` on sets, timing flow detects it). **No template concept exists** — the Workouts list has a single "new workout" entry (WorkoutBuilderView with nil id). The `Workout` model does NOT decode `session_type` (column exists in DB, unused by the app). A coach wanting a 3MT must type the text and hope the parser recognizes it.

## Why

The 3MT is a standardized test — Dr Eva's protocol is fixed: 3 minutes all-out, 25m splits, familiarisation trials, specific quality flags. A coach runs it twice a year per swimmer. It should be **one tap from the Workouts list**, prebuilt to Eva's spec, not a text-parse gamble. The template is the product's "sport scientist in the pocket" story: the test that needs no hardware, prebuilt by the protocol.

## The template

One tap → a workout prebuilt exactly to Eva's protocol:

- **Title:** "3MT — 3-minute all-out test"
- **Text (the canonical string, parser-recognized):** `3MT: 3 min all-out, 25m splits, Free`
- **Set:** 1 rep, 25m split distance, intensity `3mt`, continuous 3:00 (no interval)
- **Session type:** `3mt` (workouts.session_type — the column exists, wire it)
- **Coach notes (description):** the protocol in coach words — "All-out from the first push-off. Tap LAP at every wall. Two learning trials before the numbers are usable. Don't mix battery values across test types — watch the trend."

## Contract

### Slice 1 — Template entry point
In WorkoutsListView, alongside the existing "new workout" row: a "3MT test" row (or a menu on the + button — match the existing pattern). Tapping it creates the workout via the existing create path with the canonical text, then opens WorkoutBuilderView in edit mode (so the coach can adjust stroke/notes before saving).

Acceptance: one tap from the list → a draft workout with the canonical 3MT text, parsed to a 3mt set, visible in the builder.

### Slice 2 — session_type wiring
- `Workout` model: decode `session_type` (optional, `decodeIfPresent` — old rows decode clean)
- `createWorkout`: accept + persist `session_type` (the column exists; the create payload needs the field)
- The template passes `session_type: "3mt"`; the timing flow already detects 3mt via set intensity — session_type is the workout-level marker for the list/review surfaces

Acceptance: a template-created workout round-trips session_type = "3mt" through create → fetch → decode.

### Slice 3 — Template badge + review surface
- Workouts list: 3MT workouts get a small "3MT" badge (mono font, accentCyan — the brand signature)
- Session review: a 3MT session already shows the curve + three numbers (V0.38 slice 5) — verify the template-created workout flows through unchanged

Acceptance: template workout shows the badge; timing + review behave exactly like a typed 3MT workout.

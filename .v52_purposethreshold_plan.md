# V0.52.1 — Purposeful Threshold audit fix

## Trigger
User's exact workout ("Purposeful Threshold", 2026-09-08) fails 5 coach-visible
ways on the live LLM parser. Live parse confirms every failure in
`/tmp/purposeful-threshold.json` (5.3s, HTTP 200, degraded=None):

1. `4×150 @ 2:20–2:30` + "Each: 50@65% / 50@70% / 50@75%" → 0 fragments.
2. `4×50 @ 1:00` + "Descend: 1=70%, 2=75%, 3=80%, 4=~85%" → 0 fragments; the
   numbered ladder is dropped into a note instead of becoming a per-rep
   intensity ramp.
3. `4×100 @ 80–85%` → interval=intensity BOTH lost (interval=null, int=None).
4. `25 event rhythm / 25 easy` → 25m None + 25m easy; 'event' falls into
   unmapped_terms.
5. `unmapped_terms = ['descend', 'event']` — both false positives.

## Root cause (single design gap)
V0.52 prompt covered "Each N: 25 Drill/25 Build/.../25 Easy" (rule 18) but
NOT two distinct patterns the coach uses in this workout:

a. **`Each:` with distance-prefixed percentage sub-segments** — coach writes
   `Each: 50 @ 65% / 50 @ 70% / 50 @ 75%`. The fragment text is "50 @ 65%"
   (distance + intensity), not "25 Drill". Rule 18's slash-separated pattern
   catches the delimeter but the prompt never told the LLM that `N @ N%` is
   a per-rep composite where EACH segment carries its own distance +
   intensity. LLM collapsed to a single rg + note.

b. **`Descend: 1 = N%, 2 = N%, ...` numbered ladder** — coach writes
   `Descend: 1 = 70% / 2 = 75% / 3 = 80% / 4 = ~85%`. This is a per-REP
   intensity ladder (rep 1 → 70%, rep 2 → 75%, ...), not a composite. Rule 5
   ("numbered sub-items describe content of each rep, NOT standalone sets")
   handles the routing but the prompt never said "the numbers map to rep
   indices — emit intensity per fragment keyed on the rep index." LLM
   collapsed to a single rg with `descend` modifier.

c. **`@ N%–M%` range intensity on a repGroup header** — coach writes
   `4 × 100 @ 80–85%` inside a "3 rounds" block. The `80–85%` is the set's
   governing intensity (percent_range, not @-interval). The validator
   interprets `@ 80–85%` as an interval (1:80-style) AND drops the intensity
   because the LLM never emitted a separate intensity field. Both fields
   come back null.

d. **`event rhythm` and `race rhythm`** — same semantic (race_pace label);
   rule 6 maps 'race rhythm' but rule 7's Tier-1 list rejects it as a phrase.
   'event' alone was rejected as an abbreviation (post-fix) but the LLM was
   seeing `event rhythm` as "event" + "rhythm" and emitting 'event' into
   unmapped_terms.

## Fix

### Prompt additions (in `_llm.ts` SYSTEM_PROMPT, mirror to `supabase/` copy)

Add three new rules after rule 21:

> **Rule 22 — `Each:` / `Repeat:` / `Descend:` / `Build:` ladders**.
> When a line immediately following a set starts with the keyword
> `Each:`, `Repeat:`, `Descend:`, `Build:`, `Surge:`, `Wave:`,
> `Pyramid:`, `Climb:`, or any word ending in `:` followed by N
> numbered or sub-listed lines, the contents describe the
> composition of EVERY rep in the parent set. Two distinct
> sub-patterns:
>
> **(a) Per-rep intensity ladder** — `Descend: 1 = 70% / 2 = 75% /
> 3 = 80% / 4 = ~85%`, `Build: 1 = 65% / 2 = 70% / 3 = 75%`, `Wave:
> 1 = 80% / 2 = 85% / 1 = 80%`. Each numbered line maps to ONE rep
> in the parent repGroup (1 → first rep, 2 → second rep, etc.).
> Emit `reps` fragments (one per ladder entry) on the parent rg
> with `distance: parent.distance / parent.reps` and
> `intensity: { type: "descend" or "build" matching the header,
> label: "rep{i} N%" }`. The parent's existing
> `intensity {type:"descend"}` stays as the set-level modifier.
>
> **(b) Sub-segment composite ladder** — `Each: 50 @ 65% / 50 @ 70%
> / 50 @ 75%`, `Each: 25 scull / 25 build / 25 easy`. Each line is a
> SUB-SEGMENT of ONE rep. Emit ONE fragment per line on the parent
> repGroup with `distance: <line's distance>` and `intensity` derived
> from the line's text (`50 @ 65%` → `{type:"percent_range",
> label:"65%"}`; `25 scull` → null; `25 build` →
> `{type:"build", label:"build"}`). Sub-segments sum to the parent's
> total rep distance.
>
> Distinguishing signal: if the parent rg has distance D and the
> ladder has L lines summing to D, treat as (b) sub-segments. If the
> parent has `reps: N` and the ladder has N numbered entries
> (`1 = ... 2 = ... N = ...`), treat as (a) per-rep ladder. If the
> ladder entries contain explicit `=` percent syntax (`1 = 70%`),
> treat as (a) regardless of count. Default ambiguous case → (a)
> (numbered form is the more common Jodie's notation).

> **Rule 23 — `@ N%–M%` percent-range intensity on header line**.
> When a repGroup header carries `@` followed by a PERCENT RANGE (e.g.
> `@ 80–85%`, `@ 65-75%`, `@ 90 %`), the percent range is the set's
> GOVERNING INTENSITY — emit `intensity: { type: "percent_range",
> label: "80–85%" }` on the repGroup. The `@ N%–M%` syntax is NOT an
> interval (interval stays null unless a `M:SS` form follows the
> `@`). When BOTH `@ N%–M%` and `@ M:SS` appear in the same header
> (e.g. `4 × 100 @ 80% @ 1:30`), the `%` is the intensity and the
> `M:SS` is the interval — emit both. Examples that frequently fail
> (verify each one):
>    - `4 × 100 @ 80–85%` → `{intensity: percent_range 80–85%, interval: null}`.
>    - `8 × 50 @ 75% on 1:00` → `{intensity: percent_range 75%, interval: 1:00}`.
>    - `4 × 50 @ 1:00` → `{intensity: null, interval: 1:00}` (no percent).

> **Rule 24 — Race rhythm / event rhythm / race pace / NN-pace**
> intensity vocabulary. All four are SYNONYMS for the same race_pace
> intensity tier:
>    - `race rhythm` → `{type: "race_pace", label: "race rhythm"}`
>    - `event rhythm` → `{type: "race_pace", label: "event rhythm"}`
>    - `race pace` → `{type: "race_pace", label: "race pace"}`
>    - `200 pace` / `100 pace` / `800 pace` / `400 pace` → `{type:
>      "race_pace", label: "<distance> pace"}`
> `event` alone is NOT an intensity word — it is part of `event
> rhythm`. `race` alone is NOT an intensity word — it is part of
> `race pace` / `race rhythm`. Neither goes in unmapped_terms; the
> engine resolves the full phrase silently.

### `unmapped_terms` exclusion list (rule 7, second-pass scrub)

Add to the Tier-1 / phrase-rejection rules in rule 7 (already exists in the
form of "Reject multi-word phrases" + "Tier-1 ONLY words list"):

> **(5) Is it part of a phrase the engine resolves via rule 6 or rule 24?
> Reject if yes:** `event` (part of `event rhythm`), `race` (part of
> `race pace` / `race rhythm`), `pace` (part of `<NN> pace` /
> `race pace`), `rhythm` (part of `event rhythm` / `race rhythm`).
> **(6) Does the word appear ONLY as a section title modifier?
> Reject if yes:** `descend` (when already honored as `intensity.type
> = "descend"` on the parent repGroup; coach wrote `Descend: 1=70%
> / 2=75%...` and the set-level `descend` modifier is already
> captured — do NOT re-emit the word into unmapped_terms as a
> Tier-1 ask).

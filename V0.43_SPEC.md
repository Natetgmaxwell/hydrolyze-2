### Slice 3 — Signal computation (pure Swift service)
`SquadSignalService`: per swimmer, per form event (form_stroke + best-PB distance at that stroke, fallback 50 Free), compute gap-to-PB + trend from recorded_times (last 8 weeks), consume zones (V0.40) for "which zone are they training in" context, recovery signature (V0.42) for the detail row. Output: `SquadSignal { swimmerId, event, signal: .raceReady/.building/.offPace/.quiet, gapPercent, trendSlope }`. Unit-testable.

### Slice 4 — Squad view UI
New surface leading AnalyticsTabView (squad signals first, bands below — Q3): one row per swimmer, color dot + signal label + event, tap → existing SwimmerAnalyticsView. 0.5-second glance: name + color + 3-4 words. Never a number in the headline.

### v1.1 (follow-up, ships after 4+ weeks of gear data — Q5)
F-v squad map: scatter, x = gear (categorical resistance ordinal), y = per-100m pace at form event. Squad median + spread bands. Tap → swimmer analytics. Renders only once gear data exists (hidden otherwise).

## Q4 clarification — what the gear picker is

**The problem:** `recorded_times.gear` is structurally present but zero real rows carry it (2026-06-23 finding: all 432 rows = 'none'). The parser extracts gear *from workout text* when the coach writes it ("with paddles"), but most sets never name gear — so the calibration engine (pairing), the F-v map, and zones all compare paddles sets to bare-hand sets as if they were the same. The F-v proxy is dead without capture.

**The mechanic I'm proposing:** a one-tap inline chip row in the natural gap *between sets* on the timing screen — "Gear for this set? None / Paddles / Pull buoy / Fins / Parachute" (5 options). One tap, no modal, appears only in the set-transition moment (the same muscle memory as "which set is next"). The selected gear stamps every `recorded_time` row for that set.

- **Set-level, not per-rep** — mid-set 0.5s tap cycles can't take a gear tap; per-set is the documented design ("One tap before a set beats one tap per rep mid-set"). A squad does a paddles set together — gear is a set property in practice.
- **Prefill** — if the workout text already parsed gear, the chip shows it pre-selected (coach confirms or changes); otherwise None, with the swimmer's `preferred_gear` available as a one-tap shortcut chip (invert-the-onus: swimmer declares preference once in settings, coach confirms on deck).
- **Per-swimmer gear override** (half the squad on paddles, half not) — deferred; rare in practice, and the prefill + one-tap covers the common case.

**Why it's worth the one tap:** it's the difference between the engine calibrating apples-to-apples and apples-to-oranges. Without it, the "calibration matters" principle (VISION.md) is unfulfilled for the most common variable after distance/stroke/intensity.

**Alternative I'm NOT recommending:** a modal gear sheet at set start (breaks the non-intrusive surface rule), or per-rep gear capture (breaks the 0.5s rhythm).

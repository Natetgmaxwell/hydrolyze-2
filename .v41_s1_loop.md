## The zone-term detection rule (shared by ALL four regex sites — engine/index/on-device)

`parseZoneTerm(raw)` returns the zone word ONLY when it appears as a standalone zone term. The four zone words: `easy`, `steady`, `hard`, `sprint`. Rule:
- Match word-boundary standalone: `/\b(steady|sprint)\b/i` and for `easy`/`hard` the existing intensity blocks already prove the word is present — but zone_term must be the SPECIFIC zone word when it's a pure intensity word. **Simplest correct rule:** if the set text contains exactly one of the four zone words (standalone, word-boundary, case-insensitive), return that word lowercased; if none OR more than one distinct zone word, return null. This keeps "8×100 Steady on 1:30" → "steady", "4×50 Sprint" → "sprint", and "8×100 free" → null. Multi-zone sets (e.g. a broken swim with "fast"/"easy" fragments) return null at the SET level (the fragments carry their own intensity; the set-level zone_term is the single governing zone or null).
- Do NOT trigger on: "moderate", "cruise", "tempo", "aerobic", "threshold", "race pace", "all-out", "max", "build", "descend", "negative split". Those are intensity types but NOT the four zone terms. Zone_term is EXACTLY one of the four words when present.
- The 3MT marker (line ~741 index / ~418 _llm) already wins intensity; it does NOT set a zone_term (null). Zone-term detection must not interfere with 3MT.

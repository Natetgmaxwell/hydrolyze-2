## Why (the flywheel)

Every drop-rule strike is a datapoint: swimmer X, set Y, rep N, +0.6s off standard, needed +30s rest. Across weeks the pattern answers "Does Ariana hold pace longer than Jack at the same rest?" — the recovery signature. This slice surfaces it on the swimmer detail view in coach words, plus the revert-rate coach flag.

## Architecture you're building

The pure aggregation must be CLI-testable (macstudio is unreachable, no local Xcode — the CLI runner pattern carries the test burden, see `ios-native/Hydrolyze/Tests/CLI/build_and_run_restcountdown.sh`). So split into two files:

1. **`ios-native/Hydrolyze/Sources/Services/RecoverySignature.swift`** — PURE Swift (Foundation-only: no UIKit, no Supabase, no Combine, no async). Contains:
   - `struct RestEventRecord: Codable, Equatable, Sendable` — the DB row shape, snake_case CodingKeys (id, session_id?, workout_set_id?, swimmer_id, rep_index, rep_time_ms, standard_ms, base_rest_sec, extended_rest_sec, delta_sec, strike_count, standard_source, reverted, created_at). Mirrors `RestEventRow` but is a full Codable record (Decodable too — the service decodes the Supabase response into these).
   - `struct RecoverySignature: Equatable, Sendable` — the per-swimmer aggregate: `medianRepBeforeDrop: Int?` (median rep_index at FIRST strike across anaerobic sets), `totalStrikes: Int`, `avgDeltaSec: Double`, `avgExtendedRestSec: Double`, `revertRate: Double` (reverted rows / (strike rows + revert rows); 0 if none).
   - `struct WeeklyStrainPoint: Equatable, Sendable, Identifiable` — `weekStartISO: String` (ISO8601 of the week start, Monday), `strikes: Int`, `reps: Int`, `strikesPer100Reps: Double`. `id = weekStartISO`.
   - `enum RecoveryAggregator` (pure static funcs):
     - `static func signature(events: [RestEventRecord]) -> RecoverySignature` — median rep-at-first-strike, rates, averages. Empty input → zeroed signature with `medianRepBeforeDrop = nil`.
     - `static func weeklyTrend(events: [RestEventRecord], weeks: Int = 8) -> [WeeklyStrainPoint]` — bucket strike rows by ISO week (Monday-start) over the last `weeks` weeks. `reps` = the rep count for the week (see below for the rep-count definition).
     - `static func revertRate(events: [RestEventRecord]) -> Double` — reverted / (strike + revert); 0 if denominator is 0. Same as `signature(...).revertRate`.
     - `static func coachSignatureLine(_ s: RecoverySignature) -> String?` — nil when `medianRepBeforeDrop == nil` (no data → the VIEW hides, never shows chrome). When present, coach words: `"Drops on rep \(median) of hard sets — recovers in one rep."` (use the spec's exact example phrasing; compute `median` from `medianRepBeforeDrop`). Keep the "recovers in one rep" clause grounded: use it when the typical strikes-per-set is 1 (a strike is followed by a standard-hit, not a second strike). If you can't reliably derive recovery-pace from the data, keep the line to `"Drops on rep \(median) of hard sets."` — do NOT invent a recovery claim the data doesn't support. Document which you chose and why.
     - `static func coachRevertFlag(_ rate: Double, firstName: String) -> String?` — nil unless `rate > 0.30`. When flagged: `"\(firstName)'s extensions are usually wrong — check the standard."` (spec §Slice 3 exact copy). The >30% threshold is a LOCKED decision — hard-code it, do not make it configurable.
   - **Rep-count for `strikesPer100Reps`**: the spec wants strikes per 100 reps. The `set_rest_events` table records only strikes (one row per extension decision) + reverts — NOT every rep swum. So a true strikes-per-rep is not directly available from this table. **Decision: compute `reps` from the strike rows' `rep_index` field** — the max `rep_index` in a set approximates that set's rep count. Per week: `reps = sum over anaerobic sets of max(rep_index among that set's strike rows)`. This is an approximation (only counts reps up to the last strike); document it in a `// why` comment and in your report. It is the honest available measure and satisfies the acceptance (trend shape, coach-readable).

2. **`ios-native/Hydrolyze/Sources/Services/RecoveryService.swift`** — the Supabase fetch layer, mirroring `AnalyticsService`:
   - `final class RecoveryService`, `private let client = SupabaseService.shared.client`.

   - `func fetchRevertRate(swimmerId: String, since: Date) async throws -> Double` — fetch then `RecoveryAggregator.revertRate`.

**Related:** V0.47_DIALECT.md (term lists; this version is a corpus-driven trim), V0.51_SPEC.md (decimal-distance hotfix; this version preserves the half-pool rounding), V0.41_SPEC.md (zone_term; unaffected).

## Why

The bench scored 1.0/1.0 on all 21 `real-input-*.txt` files; the user said the parser was "still not doing the best job". The contradiction was structural — the bench:

- Scores the **regex engine** (`engine.ts`), not the deployed LLM path (`_llm.ts`).
- Had **zero entries** for the 8 `commit-jodie-*.txt` files in `expected.ts`.
- Returned **0/0** on `commit-coverage.ts` because the regex engine produces 0 set-like captures on Jodie's structured-text workouts.
- Asserted nothing on `unmapped_terms` quality (the iOS end-of-session card reads this field).
- Asserted nothing on per-fragment intensity / gear / start_type completeness.

Live calls on the 8 Jodie corpus files showed the LLM path parses cleanly (no errors, no float regressions) but quietly degrades on:

1. **Composite-set fragments lose intensity** for half the segments in Jodie's workouts (rule 16, this version).
2. **Per-fragment gear / start_type** always null at the fragment level, even when the parent rg gets them right (rule 17).
3. **Composite vs. per-rep-instruction boundary** — the LLM treats `25 scull / 25 DPS / 25 build / 25 easy` as a note instead of 4 fragments (rule 18).
4. **Multi-set summary lines** (`400 swim + 4 × 100 pull + 4 × 50`) emit as a single rg with distance=400 (rule 19).
5. **Inter-round directives** (`Take one additional minute between rounds`, `Then aerobic recovery.`) collapse into rg notes (rule 20).
6. **Pace-target context disambiguation** — `faster than 800 pace` was mapped to `sprint` instead of `race_pace` (rule 21).
7. **`unmapped_terms` noise** — `a1`, `a2`, `dps`, `fnt`, `mod` reach the iOS card as Tier-1 asks (Tier-2 exclusion set, this version).
8. **`unmapped_terms` over-asking** — `easy`, `strong`, `relaxed`, `max`, `fast`, `all-out`, `moderate` were in Tier-1 and asked on every parse, even though the engine has a defensible industry-standard default for each (Tier-1 trim, this version).

The fixes are split into three files: prompt rules (16–21) in `_llm.ts` SYSTEM_PROMPT, dialect-term list moves in `_dialect-terms.ts` + `_dialect-detector.ts`, and the validator-level `parseIntensity` fix for `strong` (Tier-2 silent → aerobic) + `mod` shorthand.

## Boundaries

- **Always**: prompt changes are additive (rules 16–21 alongside 1–15, not replacing them); the 4-place sync invariant (prompt / `_dialect-terms.ts` / `_dialect-detector.ts` / engine.ts default-rpe table) holds.
- **Ask first**: moving words between Tier-1 and Tier-2 for coaches other than Jodie (the audit is corpus-driven on Jodie specifically — other coaches may have different patterns); adding new fragment-level fields beyond gear/start_type.
- **Never**: removing the iOS end-of-session card; asking `easy` after the coach confirms (never-ask-twice invariant is sacred); emitting unmapped_terms from a section title; asserting on intensity labels in determinism tests (intensity IDs only — the coach's word is non-deterministic).

## Lessons encoded

- **The bench CAN lie.** A 1.0/1.0 score on the regex path is NOT a 1.0/1.0 score on the LLM path. The two are scored by separate code paths and have separate expected sets. Adding a new corpus without updating the expected set makes the bench silently blind to that corpus.
- **Corpus-driven term lists win.** The original Tier-1 list was top-down ("these are the words coaches use"); the Jodie audit revealed half the Tier-1 words appear in 6+ workouts and have one defensible industry-standard RPE band — they belong in Tier-2. The list should be re-derived from the corpus every time it changes.
- **Per-fragment completeness is a separate axis from set-level completeness.** The LLM emits a correct rg structure but loses per-fragment context — pairing engine keys on the per-fragment signal and silently underpredicts when it's null. The fix lives in the prompt (rule 16), not in the validator (the validator can't backfill from parent text without overfitting).

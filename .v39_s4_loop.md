### 4a. Model accumulates an event trail (pure logic, TDD)

Add to `RestCountdownModel`:
- `private(set) var restEvents: [RestEvent] = []` where:
  ```swift
  struct RestEvent: Equatable, Sendable {
      let swimmerId: String
      let repIndex: Int
      let repTimeMs: Int
      let standardMs: Int
      let standardSource: RestStandardSource
      let baseRestSec: Int
      let extendedRestSec: Int
      let deltaSec: Int
      let strikeCount: Int
      let reverted: Bool
      let eventType: RestEventType   // .strike or .revert
  }
  enum RestEventType: String, Equatable, Sendable { case strike, revert }
  ```
- In `evaluate(...)`, append a `RestEvent` for EVERY evaluation that is a strike (`struck == true`), with `eventType = .strike`, `reverted = false`. Do NOT append for non-strikes (a non-strike is not an "extension decision" — the spec says "one per extension decision").
- In `revert(swimmerId:)`, append a `RestEvent` with `eventType = .revert`, `reverted = true`, and the fields of the strike being reverted. **Problem**: `revert(swimmerId:)` currently receives only the swimmerId. The strike being reverted is the LAST strike event for that swimmer. Look it up from `restEvents` (the last `.strike` for that swimmerId) and use its fields (repIndex, repTimeMs, standardMs, standardSource, baseRestSec, extendedRestSec-before-revert, deltaSec, strikeCount). If no prior strike exists for that swimmer, the revert is a no-op (append nothing, or a benign event with deltaSec 0 — judge; the VM only calls revert after a strike badge showed).
- `reset()` clears `restEvents` (a new set starts a fresh trail).
- A `RestEventRow: Encodable` struct for the DB insert (id, session_id, workout_set_id, swimmer_id, rep_index, rep_time_ms, standard_ms, base_rest_sec, extended_rest_sec, delta_sec, strike_count, standard_source, reverted, created_at). ### 4b. Persistence — write set_rest_events on set completion

**Where**: The drop rule fires in the single-swimmer flow (Slice 3's scope: per-swimmer attribution is unambiguous). So the save hook is the **single-swimmer branch** of `save(sessionId: nil)`. After `timingService.saveSession(session)` succeeds (or in a non-fatal block after it), if `restModel` is non-nil and has accumulated `restEvents`, write them.

- Add `TimingService.saveRestEvents(_ rows: [RestEventRow], sessionId: String?, workoutSetId: String?) async throws` — inserts into `set_rest_events` via `supabase.from("set_rest_events").insert(rows)`. Session_id and workout_set_id are optional (the single-swimmer flow sets `session_id: nil` on recorded_times today; match that — pass the workoutSetId through, session_id nil unless a sessionId is available).
- In `save(sessionId: nil)` single-swimmer branch, after `saveSession` succeeds:
  ```swift
  // V0.39 Slice 4 (2026-08-18): persist drop-rule rest events.
  // Non-fatal — the recorded times are the source of truth; a
  // rest-events write failure must not fail the save (the coach
  // still sees their times). The reverted flag preserves
  // coach-is-authority: a reverted extension is recorded (the
  // flywheel learns the coach disagreed) but the rest was not
  // extended.
  if let restModel, !restModel.restEvents.isEmpty {
      do {
          let rows = restModel.restEvents.map { ... RestEventRow ... }
          try await timingService.saveRestEvents(rows, sessionId: nil, workoutSetId: workoutSetId)
      } catch {
          log("set_rest_events insert FAILED (non-fatal): \(error.localizedDescription)")
      }
  }
  ```
- The single-swimmer flow calls `reset()` after save — ensure `reset()` clears `restEvents` so a retry doesn't double-write. (It already clears; just confirm the trail is cleared AFTER the write, which it is since reset is called at the end.)

**Constraint**: A reverted extension is written with `reverted = true`. No rows for aerobic sets (the model is nil for aerobic → no events → no write, automatically).

## 1. The two languages, and the dividing rule

Every workout is written in two languages at once.

- **Shared grammar** — universal swim notation. `8 x 100 free on 1:30` means the same thing for every coach on earth. The LLM already speaks it (see `_llm.ts` rule 6: fast→sprint, easy→easy, moderate/steady/cruise/smooth→aerobic…).
- **Coach dialect** — words whose meaning lives in one coach's head. `moderate`, `easy`, `cruise`. No model can know Jodie's `moderate`; ground truth can only enter the system by asking her once.

**The dividing rule:** a word is *shared grammar* if two experienced coaches would assign it the same RPE band every time. If two coaches could meaningfully disagree, it is *dialect*.

**Worked examples**

1. `8 x 100 free on 1:30` — fully shared. Nothing to ask.
2. `8 x 100 easy on 1:30` — hybrid. Structure shared; `easy` is dialect (coaches map it 3, 5, or 7). Ask once.
3. `8 x 100 build` — progression dialect. The *pattern* (each rep faster) is shared grammar; the *intensity envelope* (start RPE → end RPE) is dialect. Two-point capture (§5 Q2).

Ask-options for every term: **RPE 4-5 / 6-7 / 8-9 / 10**. Progressions (`build`, `descend`) get two picks: start and end. v1 has no distance-specific mapping — the 4 buckets are the resolution vocabulary.

> **Decision 2026-08-21 — distance-specific mappings are out of scope for v1.** No `min_distance`/`max_distance` columns; no `user_term` encoding convention. If coaches ask, collect the demand and decide in v2.

**Tier 2 — silent default + override indicator** (never interrupts the coach): `recovery` 3-4, `aerobic` 5-7, `smooth` (→aerobic), `activation` 5-6, plus explicit numeric forms the coach already wrote (`RPE: 6/10`, `Zone 2`, `80%` — these are shared grammar, the coach did our work for us).

**Promotion rule (proposed):** any Tier-2 term seen ≥3 times across ≥2 sessions for one coach gets promoted to Tier 1 for that coach — asked once, then mapped.

## 4. Ask UX contract

**When the prompt fires** *(decided 2026-08-21 — interactive product surface, especially early)*:

1. Coach finishes the session, taps Done.
2. Edge function parses; response includes `unmapped_terms: [...]` (terms hit in this workout with no `coach_vocabulary` row).
3. iOS shows **one end-of-session vocabulary card**: all new terms, each with the coach's original line as context, RPE bands + distance-specific, defaults pre-selected.
4. Coach confirms/adjusts → `VocabularyService.saveMapping` upserts. Thirty seconds, once per new word, never again.

Inline per-set prompting is explicitly **out** for v1 — it interrupts session flow. Revisit only with usage data.

**Never-ask-twice invariant** *(decided 2026-06-16)*: once `(coach_id, user_term)` exists, the term resolves silently, forever, across re-parses and new sessions.

**Override indicator** *(decided 2026-06-16)*: silently-resolved sets show a small vocab marker (tap → shows the mapping, tap-through to edit). Visible, unobtrusive, never blocking.

**Re-parse rule** *(locked — V0.35 invariant)*: fragment ids are `frag-` + sha1(`sourceLine:orderIndex`) — **ids hash the text, never the mapping.** A mapping added or edited later must not change any fragment id, or `recorded_times.fragment_id` orphans. Mapping edits update displayed RPE; ids and history stay put.

## 5. Pipeline wiring

**The per-coach context block.** The edge function, which has the coach's auth context, reads `coach_vocabulary` before the LLM call and injects at the top of the system prompt:

```
COACH VOCABULARY (this coach's own words — override the general rules below):
  easy → RPE 4-5
  moderate → RPE 6-7
  build → RPE 6 → 8 (progression)
When one of these words appears, use this RPE unless the surrounding text clearly contradicts it.
```

The LLM keeps owning reps/distance/stroke/structure (shared grammar); it inherits intensity for mapped terms (dialect). Response gains one field: `unmapped_terms`.

**Sync surfaces for this change (the 4-place rule, plus the DB — the V0.35 lesson):**

1. `scripts/parser-bench/` prototype (+ bench case: mapped term resolves; unmapped term lands in `unmapped_terms`)
2. `_llm.ts` (prompt + response shape)
3. edge `index.ts` (vocabulary fetch + injection + `unmapped_terms` passthrough)
4. iOS (`VocabularyService` cache feeds nothing here — the *server* resolves; iOS renders the card + writes mappings)
5. **DB**: `coach_vocabulary` — no migration needed for v1 (distance-specific is explicitly out)

Also fix the drift in the same pass: Swift `ambiguousTerms` realigned to the final Tier-1 list (single source of truth: a shared constants file or generated list — stop hand-maintaining two lists).

**Verification (per repo discipline):** bench `score.ts` stays 1.0; ladder verifier 9/10+ after deploy; one worked curl proving `unmapped_terms: ["moderate"]` on a fresh coach, then silence after a mapping is saved.

## 7. v1 scope summary (for build profile)

**In scope**
- Single source-of-truth term list (`shared/constants/dialect-terms.ts` generated from a single table) — kills Swift↔engine drift in the same pass.
- Edge function reads `coach_vocabulary` for the authenticated coach, injects the per-coach context block into the LLM system prompt, and adds `unmapped_terms: string[]` to the parse response.
- End-of-session vocabulary card on iOS (one prompt, all new terms, context line shown, RPE bands pre-selected).
- 2-point capture for `build` / `descend`.
- Re-map confirm dialog (count of affected past sets shown).
- Re-alignment of Swift `ambiguousTerms` set to the single source.

- Distance-specific mappings (Q1).

- Single-RPE picker granularity (Q5).
- Anything below RPE 4 in the picker.

# V0.53.1_SPEC — send-off belongs to the whole rep + no timing affordance on easy fragments

Branch: fix/fragment-decimal-distance-decode
Status: WORKING-TREE. Swift patch in progress. Build target: macstudio-tailnet.

## Problem (verbatim from Nathan's dictated message, 2026-09-08)

> "So what you've done is just tag continuous on to the instructions for the set
> fragment. I want you to show it in the UI more than tell it. ... we can pretty
> well assume that coaches won't need to capture a time for the easy swims.
> This is more on feel, so we can try and minimalise the UI by not having the
> option to record a time for the easy swims. And when you've said 4 times 50s,
> the whole 50 is on a minute, not the individual 25s."

Two independent items, both UI-side. The parser/edge function data was already
correct per V0.53 (live curl confirmed: `reps=4 dist=50 interval='1:00' frags=2
continuous`, fragments carry NO interval field — interval lives only on the
repGroup). What's wrong is the iOS rendering.

## Scope (this slice)

### Item 1 — Send-off belongs to the whole rep

`4 × 50 @ 1:00` → each 50 (both 25s together) is on 1:00. The interval must
render ONCE on the rep header, not repeated per fragment row.

**Diagnosis (data vs UI):**

Live JSON for jodie-09 line 39-40:

```
sec1.ns0.rg2: reps=4 dist=50 interval='1:00' frags=2
  frag0: dist=25 intensity={'type':'race_pace', label:'event rhythm'} restAfter=null
  frag1: dist=25 intensity={'type':'easy',       label:'easy'}           restAfter=null
```

Interval is on the repGroup ONLY. ✓ parser correct.

**UI fault** (WorkoutPreview.swift:1337-1342): FragmentCTARow renders
`MetadataBadge(text: "@ \(pace)", ...)` whenever `paceTargetText` is set.
Inside `PairRepGroupRow` (line 1632-1646), every child fragment row gets
`paceTargetText: paceTargetText` from the parent — so the badge appears
TWICE: once-per-fragment, and the repGroup has no place it shows the
send-off at all (PairRepGroupRow header line 1657+ only renders
`reps × dist [stroke]`, no interval).

**Fix:**

1. `PairRepGroupRow.headerLine` renders the interval once, on the parent
   header. Format: same `MetadataBadge(text: "@ \(pace)", color: textMuted)`
   chip the fragments used — visual consistency, single appearance.
2. `FragmentCTARow` accepts `showPaceBadge: Bool = true`. Default true
   preserves the single-fragment call site at line 401-414 (the only place
   it needs to). PairRepGroupRow passes false when instantiating (line
   1632) — parent header already owns it.

### Item 2 — No timing affordance on easy fragments

Coaches don't time easy swims — feel-based. Minimise: easy fragments get no
play button, no Button wrap, no launch path. Recorded-time chips (if any)
still render so previously-captured times stay visible (read-only signal).

**Gate (existing taxonomy):** `ParsedIntensityType.easy`. Engine maps
`easy | recovery | warm-up | ez | relaxed` → `type: easy` (supabase/functions/
parse-workout/_llm.ts line 560). Already a first-class type. Use it.

**Why gate at FragmentCTARow:** the row is the addressable unit. PairRepGroupRow
shouldn't know about intensity taxonomy (it groups fragments; it doesn't
classify them). The fragmentation of timing decisions lives at the row.

**Computed bool:** `isTimable: Bool { fragment.intensity?.type != .easy }`.
Default true. False when intensity is nil AND label is easy-leaning is
deliberately NOT included — we use only the typed signal to avoid invented
lists (per dispatch). nil intensity = assume timable (drills, hold rates,
descriptors don't have an easy type and stay timable as before).

**Render:**

| Element | `isTimable == true` (today's behavior) | `isTimable == false` (new) |
|---|---|---|
| Play icon / retap icon | shown | hidden |
| Row tap → launch timing | active | inactive (static content only) |
| Recorded-time chips | shown if present | shown if present (read-only history) |
| Confidence badge, gear, start, suit, distance/intensity text | shown | shown |

**Non-composite rows (line 401-414):** a single `25 easy` outside a
composite IS easy and should also drop the play icon. The gate at the row
covers both cases — no extra plumbing needed.
